# Project Ascent — instructions for Claude Code

Climbing-route overlay for **ArtRock** (Austrian climbing-wall maker), started at the Tirol Hackathon, 5–6 Nov 2026, challenge CH-12. Owner of this repository: Emilio Loredo.

## The project in brief

A wall is photographed and mapped once. After that, pointing a camera at it draws a chosen route onto the real holds, live, instead of tape, LED systems (~$13,750 a board) or projectors. Routes are picked from a database, generated by rules for the skill a climber wants to train, or built by hand. Later, the camera can also watch the climb.

- **Primary user:** Lena, a regular climber at a small gym who knows her weakness but not what to climb. Then Max (14, outdoor, gamification, a creator of routes) and Laura (shoulder rehab; the therapist is the buyer).
- **Core idea shared by all three:** a route is a set of holds, tagged by what it trains, drawn on the live view of the wall.
- **Gap in the market:** LED boards need one fixed layout; photo apps show a static photo; ClimbAI analyses movement but knows nothing about the wall. Nobody draws routes live on custom walls.

3. The team's own ideas (blog, chat, smartwatch, …) are roadmap unless a decision in the docs says otherwise.

## Project phase — read this before building anything new

**Current phase: laptop prototype, with the phone as a camera.** On 6 Nov Emilio decided to leave the laptop-only phase for one thing: `python ascent.py serve`, a local HTTPS server on the laptop, so a smartphone on the same Wi-Fi can be the camera (the original goal is a smartphone prototype). Nothing else about the phase changed. Until the team deliberately decides on a platform (`docs/08-status-and-next.md`, "Moving beyond the hackathon"):

- Keep the prototype in `ascent.py`, Python, run from a terminal.
- **The local server (`serve`) uses only the Python standard library** (`http.server`, `ssl`, `threading`): no web framework, no build step. Phone pages are plain HTML and JavaScript in `web/`. The vision work (tracking, motion tracking, saving scans) runs on the laptop through the same functions the CLI uses.
- The server is local only: HTTPS with a self-signed certificate (made on first run; the `cryptography` package is allowed for that, as an optional import), an access code in the phone URL, no cloud, no accounts. It is not the shared server that accounts and sharing need.
- Dependencies: OpenCV (`opencv-contrib-python`) and numpy. **MediaPipe is allowed for motion tracking only**, imported inside the command that uses it, so everything else keeps working without it. **`cryptography` is allowed only to make the certificate for `serve`**, imported inside it.
- Store data as JSON files under `walls/` (and a similar folder for new data, such as logbooks). No database server, no web app, no mobile build.
- Features that need a shared server (accounts, community feed, chat, sharing between people) are **designed and mocked**, not built, in this phase. The local `serve` doesn't change that.
- If the user asks for something that breaks these rules, say so and ask whether they're deciding to leave the prototype phase. Don't silently refuse and don't silently comply.

## Product rules that never change

- **Never draw an overlay when the wall isn't locked.** Draw nothing and say which way to move.
- **Walls have versions.** Re-scanning archives the old version and its routes; nothing is deleted.
- **Route generation is rules-based.** Every move within reach (0.55 × climber height), explainable. No AI model in the generator.
- **Grades are estimates**, always shown with `~`.
- **Overlay accuracy target:** within about 3 cm of the hold at 3–5 m; above 7 cm it points at the wrong hold and counts as broken.
- **Gamification must not push people to climb harder alone** — especially minors: no streak penalties, no hardest-grade leaderboards.
- **Videos show people.** Process on the device, keep recordings out of git (already in `.gitignore`), never add mood or emotion analysis (prohibited under the AI Act in education and the workplace).
- **The app is a tool for therapists**, never a judge of whether a patient's movement is safe.

## How to work in this repository

- **`git pull` before starting.** Emilio also works on this repository from other Claude sessions.
- Make one small change, run it, then commit. Commit only working states.
- After any code change, run `python tests/rehearsal.py` — all checks must pass. Add checks for new behaviour.
- **Don't run `scan`, `build` or `live` yourself.** They open windows a person has to click and ask for typed input. Ask the user to run them in a separate terminal and paste any error back.
- Keep printed and on-screen strings ASCII-only: OpenCV's text renderer and some Windows consoles can't show other characters.
- Don't change the `wall.json` or route formats without a reason; existing scans must keep loading. If a format must change, keep reading the old one.
- The team are not professional developers. Before larger changes, explain the plan in plain language and wait for an OK. After changes, explain what changed and how to check it.

## Known gaps

- Not yet tested with a real webcam, real Windows windows, or the real ArtRock panel in venue light.
- The phone pages (`serve`) are tested headlessly with synthetic frames, not yet on a real iPhone or Android phone.
- Photo matching may fail on low-texture walls — use `--markers`.
- Flat walls only; partial resets (a few holds moved) aren't detected.
- Logbook, profiles, progress, recommendations, routes filters, safety card and challenges (6 Nov) are local-only: personal data in `logbook/`, `profiles/`, `challenges/`, all out of git. Sharing between people still needs the server.
- Motion tracking with audio feedback (`track`) is a minimal first version: by sticker colour (default, for the puppet demo) or MediaPipe (`--touch pose`). Not yet tested with the real puppet, the prop wall or a real person; no owner yet (`docs/08-status-and-next.md`).
- Demo setup (6 Nov): the phone is a webcam for the laptop (Camo/DroidCam, `--camera 1`); the phone web pages from `serve` are kept but not used.
